# Missing CSS.escape() for stableReportId in attribute selector

## Problem Statement

In `report-minimap.tsx`, the `stableReportId` is string-interpolated directly into a CSS attribute selector without escaping. The same file correctly uses `CSS.escape(h.domId)` for heading IDs on the same lines, but the `reportId` was missed.

Current IDs are generated by `createId()` (`Math.random().toString(36).slice(2, 10)`) which only produces safe alphanumeric characters, so there is no active exploit. However, if ID generation ever changes (e.g., server-provided IDs in a production build), this could cause a `SyntaxError` or allow selector escape.

## Findings

**File:** `src/components/chat/report-minimap.tsx`
**Lines:** 46 and 130

```ts
// CURRENT — vulnerable pattern
const reportEl = scroller.querySelector<HTMLElement>(`[data-deep-report-id="${stableReportId}"]`);

// FIXED — should be
const reportEl = scroller.querySelector<HTMLElement>(`[data-deep-report-id="${CSS.escape(stableReportId)}"]`);
```

The same fix is needed in both the `updateFromScroll` callback (line 46) and the click handler (line 130).

Note: `CSS.escape(h.domId)` is already correctly used on lines 50 and 131 — this is a consistency gap.

## Proposed Solutions

### Option A: Add CSS.escape() (Recommended)
Two-character change at lines 46 and 130. Zero risk.

### Option B: Validate reportId at the point it's passed
Ensure `msg.id` values are always alphanumeric at the type level. More defensive but more invasive.

**Recommended: Option A**
