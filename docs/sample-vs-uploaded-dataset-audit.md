# Sample vs. Uploaded Dataset Feature Parity Audit

**Date:** 2026-03-31
**Scope:** Every feature area in Baby Sentinel, comparing handcrafted sample datasets against uploaded/dynamic datasets.

---

## Executive Summary

Uploaded datasets suffer from **systematic feature degradation** across the app. The root cause is that schema enrichment (`schema-enricher.ts`) generates some metadata (agents, prompts, domain hints) but skips critical fields (events, dateRange, entityName, reportMeta). Many features silently degrade rather than warning the user, creating a confusing UX gap between the polished sample dataset experience and the uploaded dataset experience.

### Severity Breakdown

| Severity | Count | Description |
|----------|-------|-------------|
| 🔴 BROKEN | 5 | Feature completely non-functional for uploaded datasets |
| 🟠 DEGRADED | 8 | Feature works but quality/UX significantly worse |
| 🟡 MINOR | 4 | Cosmetic or edge-case issues |
| ✅ WORKS | 5 | No meaningful difference |

## 🔴 BROKEN — Features That Don't Work on Uploaded Datasets

### 1. Analytics Explorer (Trends / Funnel / Retention)

**Root cause:** `DatasetConfig.events` is optional and NEVER generated by enrichment.

**What happens:**
- `dataset?.events ?? []` → empty array → EventPicker has nothing to show
- "Add Event" button never renders (guarded by `availableEvents.length > 0`)
- All 3 tabs show "Select an event to start exploring" with nothing to select
- Breakdowns never render (guarded by `allProperties.length > 0`)
- Explorer controls bar renders uselessly (chart type, granularity selectors with no data)

**Affected files:**
- `src/app/explore/page.tsx:48` — eventCatalog = []
- `src/components/segments/segment-workspace.tsx:77` — same in segment explorer
- `src/components/explorer/event-picker.tsx:47` — AddEventButton hidden
- `src/hooks/use-funnel.ts:23` — blocks on steps.length < 2
- `src/hooks/use-retention.ts:22` — blocks on missing startEventId

**Sample datasets with events:** quickhelp (30), vastu-hfc (25), gameramp (3), alpha (3)

### 2. Store / Catalog Features

**Root cause:** 100% hardcoded mock game IAP data.

- `src/lib/store-data.ts` — MOCK_SKUS (gems, battle passes, skins), MOCK_PLAYERS, MOCK_TRANSACTIONS
- `src/lib/store-store.ts` — All CRUD reads from MOCK_* constants
- Store insights hardcoded: "JP localization gap", "banned players", "whale detection"
- No dataset mapping config exists

**Impact:** Store page shows identical game economy data regardless of dataset.

### 3. Scouts

**Root cause:** 100% hardcoded domain-specific reports.

- `src/lib/scout-data.ts:30-579` — Revenue Deep-Dive references "whale profiles", "Android gap", "ARPPU"
- Scout definitions reference hardcoded tables: `stores_rawdata`, `events_hybrid`, `installs`
- Report data is static, never queries real data

**Impact:** Scout reports show game/ecommerce metrics for any dataset.

### 4. Segment Explorer Panel (in Segment Workspace)

**Root cause:** Same as #1 — no events means the "Explore Events" button in segment Overview opens an empty panel.

- Button visible on all segments but leads to dead UI
- `segment-workspace.tsx:506-518` passes empty catalog to ExplorerConfigPanel

### 5. Funnel/Retention Save Bug

**Root cause:** Save button validation only checks Trends tab.

- `explore/page.tsx:199` — `disabled={!trends.config.events.length && activeTab === "trends"}`
- Funnel and Retention tabs can save empty/invalid configs
- Loaded saved charts show empty state

## 🟠 DEGRADED — Features That Work But Are Significantly Worse

### 6. Metrics — Not Auto-Generated on Upload

**Root cause:** Upload flow doesn't trigger metric generation.

- Sample datasets: preseeded via `PRESEEDED_METRICS` in `metric-data.ts`
- Uploaded datasets: metrics page shows empty state with "Generate Metrics & Tree" CTA
- User must manually click generate button — breaks "instant gratification" pattern
- `src/app/api/datasets/upload/route.ts` — calls `enrichDataset()` but NOT metric generation

### 7. System Context / LLM Persona Quality

**Root cause:** Two-tier quality based on enrichment success.

- Sample datasets: handcrafted domain-specific personas with detailed instructions
- Uploaded datasets (enrichment succeeds): LLM-generated persona — decent but less focused
- Uploaded datasets (enrichment fails): generic persona — "You are Actioneer, an AI analytics assistant"
- `src/lib/prompts/schema-generic.ts:96-109` — generic context has no domain hints, no persona focus
- Enrichment failure is **silent** — user has no visibility into quality degradation

### 8. Currency Formatting

**Root cause:** Optional field with unsafe defaults.

- Sample datasets: explicit (`$`, `₹`)
- Uploaded datasets: auto-detected during enrichment OR falls back to hardcoded `₹`
- `src/components/chart/chart-core.tsx:68,96` — fallback is `₹`
- `src/lib/dataset-context.tsx:43` — DEFAULT_META has `currency: "₹"`
- US data uploaders see rupee symbols on all charts

### 9. Entity Catalog Size (@ Mentions)

**Root cause:** Uploaded datasets start with zero pre-built entities.

- Sample datasets: 20-30 pre-materialized metrics, curated segments possible
- Uploaded datasets: 0 metrics, 0 segments until user creates them
- `src/lib/entity-registry.ts:52` — `getAllMetrics(datasetId)` returns empty for fresh uploads
- @ mention autocomplete works but has nothing to suggest

### 10. Subagent Task Quality (Deep Research)

**Root cause:** LLM-generated vs hand-optimized query descriptions.

- Sample datasets: hand-written `queryDescriptions` per agent (e.g., "CPI by channel and OS")
- Uploaded datasets: LLM-generated descriptions — less specific, sometimes generic
- Falls back to generic descriptions if enrichment fails (`sql-generator.ts:101-114`)
- All 6 agents still run — but ask less focused questions

### 11. Suggested Prompts Quality

**Root cause:** LLM-generated vs hand-curated.

- Sample datasets: 6 hand-optimized domain-specific prompts
- Uploaded datasets: LLM-generated (if enrichment succeeds) or generic fallbacks
- Enrichment error caught silently: `catch (enrichErr) { console.warn(...) }`
- No caching of generated prompts — unenriched uploads call Gemini on every request

### 12. Segment Generation Quality

**Root cause:** Enrichment produces fewer domain hints than handcrafted configs.

- Sample datasets: 15+ hand-written domain hints (e.g., Alpha's "DATE FORMAT CRITICAL" gotchas)
- Uploaded datasets: 3-5 LLM-detected hints — less specific
- `src/lib/prompts/segments.ts:33` — uses `schemaMap.domainHints` in prompt
- Segment SQL quality directly correlates with hint quality

### 13. Board Generation Quality

**Root cause:** Missing dataset context in chart inference.

- `src/lib/chart-inference.ts:225` — `ChartContext.datasetHints` defined but NEVER populated by callers
- `src/app/api/board-generate/route.ts` — uses dataset.currency for hero metrics only
- `src/app/api/board-from-research/route.ts:153` — calls `inferChartSpec()` with NO dataset hints
- Currency detection falls back to regex patterns (`revenue|spend|price`) — custom metric names miss formatting

## 🟡 MINOR — Cosmetic or Edge-Case Issues

### 14. Entity Name

- Sample datasets: explicit (`players`, `borrowers`, `customers`)
- Uploaded datasets: undefined, falls back to "users" in some places
- No automatic detection from `userIdField` (e.g., `customer_id` → "customers")
- Inconsistent: some components say "users", others say "customers"

### 15. Welcome Subtitle

- Sample datasets: curated (e.g., "Mobile gaming user acquisition and monetization")
- Uploaded datasets: generic `"Ask anything about your ${label} data."` until enrichment
- Low-impact — functional but generic

### 16. Date Range (DuckDB Uploads)

- CSV uploads: date range computed synchronously ✅
- DuckDB uploads: computed in background task — `dateRange: undefined` initially
- Race condition: user sees "All available data" then it updates
- Text-to-SQL prompts lack date context until background task finishes

### 17. Onboarding Flow

- Onboarding wizard tracks UI learning ("send-query", "view-report", "explore-data")
- No dataset readiness flow for uploads (no schema walkthrough, no enrichment status)
- Welcome modal has hardcoded labels for sample datasets; generic fallback for uploads

## Systemic Root Causes

1. **Enrichment is fire-and-forget** — Upload saves immediately, enrichment runs async. UI has zero visibility into enrichment status or quality. Failures are swallowed with `console.warn`.

2. **No event generation pipeline** — Schema enrichment generates agents, prompts, metrics definitions, domain hints — but never events. Events require mapping data patterns to `EventDefinition[]` with `filterColumn`/`filterValue`/`properties`, which is a distinct capability that doesn't exist.

3. **Silent degradation over explicit errors** — Missing currency shows `₹`, missing events shows empty picker, missing entityName shows "users". Users never learn their dataset is misconfigured.

4. **Hardcoded demo data in production paths** — Store, Scouts, and parts of Connectors ship mock data that renders regardless of active dataset.

5. **No post-upload configuration wizard** — Uploaded datasets need user input for `userIdField`, `dateField`, `dateRange`, `entityName`, `currency` — but there's no UI to collect these. The upload flow guesses and moves on.
