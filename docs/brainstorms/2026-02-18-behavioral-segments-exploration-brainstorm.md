# Behavioral Segments Exploration

## What We're Building

A visual, personality-driven behavioral segments experience that evolves the existing `/segments` page. Users land on a **card gallery** of LLM-named behavioral segments (like the SIMS Mobile player segments: "Ran out of gas", "Content Monsters!"), each with a distinct identity, accent color, and key stat. Clicking into a segment opens a **behavioral profile** that leads with identity (who they are, defining traits) and follows with performance metrics (how they perform). Users can push segments to channels and ask follow-up questions about any segment via chat.

The backend segmentation engine (feature extraction, clustering, profiling) is assumed to exist. This brainstorm covers the frontend experience only.

## Why This Approach

**Considered:**
- **A: Card Gallery + Profile Drawer** (chosen) - Visual cards for behavioral segments, existing table for manual segments, rich profile detail view
- **B: Unified List with Rich Previews** - Single list with expandable rows. Simpler but loses the gallery personality feel
- **C: Dedicated Explore Tab** - Separate tab for behavioral exploration. More freedom but fragments the segments experience

**Chose A because:** It delivers the visual impact of the SIMS-style gallery (segment personality front and center) while naturally coexisting with existing manual SQL segments on the same page. Progressive disclosure scales well regardless of segment count.

## Key Decisions

- **Evolve existing /segments page**: Behavioral segments are a richer "type" of segment, not a separate feature. The page shows a card gallery for behavioral segments above the existing table for manual segments.
- **LLM-generated personality**: Names, descriptions, and behavioral summaries are generated by Gemini from the segment's feature profile. No manual curation needed. Fully automated.
- **Profile-first detail view**: Segment detail leads with behavioral identity (name, description, defining traits as tags, what distinguishes them) then shows performance metrics below (retention, revenue, engagement). Identity before numbers.
- **Actions = Push + Ask**: Users can push segments to integrations (existing flow) AND ask natural-language follow-up questions about a specific segment, which opens chat pre-filled with segment context. This is the insight-to-action loop.
- **Scalable card gallery**: Must work for 3 segments or 30. Grid layout with accent colors to differentiate. Each card shows: name, one-line summary, user count with trend, accent color.

## Frontend Components (Conceptual)

### Segments Page (`/segments`)
1. **Behavioral Segments Gallery** (top section)
   - Card grid (responsive: 2-3-4 columns depending on viewport)
   - Each card: accent color strip, LLM-generated name, one-line behavioral summary, user count + trend badge
   - Click navigates to segment detail

2. **Manual Segments Table** (below gallery)
   - Existing table/list view for SQL-defined segments
   - "New Segment" button (existing create modal)

### Segment Detail Page (`/segments/[id]`)
1. **Behavioral Profile Section** (top)
   - Large name + description
   - Behavioral traits as tags/chips (e.g., "High engagement", "Price sensitive", "Browse-heavy")
   - "What makes this segment different" summary

2. **Performance Metrics Section** (below)
   - Key KPIs: user count, revenue contribution, retention rate, avg order value
   - Optional: retention curve chart, engagement distribution

3. **Action Bar**
   - Push to integrations (existing)
   - "Ask about this segment" button (opens chat with segment context)

### Data Model Extensions
- `SegmentDisplay` needs: `behavioralTraits: string[]`, `accentColor: string`, `differentiator: string` (what makes them unique)
- `type` field distinguishes `behavioral` vs `manual` (already has `dynamic | static`)

## Open Questions

- **Accent color assignment**: Should colors be deterministic (based on segment index/hash) or LLM-chosen? Deterministic is safer for consistency.
- **Empty state**: What does the gallery look like before behavioral segments exist? Placeholder card with "Run analysis to discover segments"?
- **Refresh/staleness**: How often do behavioral segments update? Should the UI show a "last refreshed" indicator?
- **Segment comparison**: Deferred for now, but comparing two segments side-by-side would be a natural next feature.
